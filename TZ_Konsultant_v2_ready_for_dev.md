# ТЗ v2 (Ready for Development): веб-приложение «Консультант по проектам»

## 1. Цель и результат MVP
**Цель MVP:** за один пользовательский сценарий получить 5 релевантных AI-инициатив по компании и пройти по выбранной инициативе структурированную консультацию в чате.

**Сценарий успеха:**
1. Пользователь вводит URL компании.
2. Система собирает контекст и показывает 5 шагов прогресса.
3. Система генерирует 5 карточек идей.
4. Пользователь открывает 1+ идей в табах и проходит 5–7 вопросов.
5. Система возвращает финальную консультацию (выгода, сроки, бюджет, риски, critical points).

## 2. Границы работ (Scope)
### In Scope (MVP)
- Анализ 1 домена за сессию.
- Генерация 5 идей на основе собранного контекста.
- Перегенерация идей без повторного парсинга.
- Чат с табами по проектам, поддержка single/multi/free ответов.
- Настройки API-ключа (demo) + безопасный режим хранения для production.

### Out of Scope (после MVP)
- Личный кабинет и многопользовательские роли.
- Интеграции с CRM/ERP.
- Полноценная BI-аналитика и экспорт в сторонние системы.

## 3. Архитектура решения (MVP)
### Frontend
- SPA на React + TypeScript.
- Экран 1: ввод URL + статусный блок анализа.
- Экран 2: список из 5 карточек идей + «Перегенерировать».
- Экран 3: двухколоночный чатовый layout с табами.
- State: `analysis`, `ideas`, `chatTabs`, `activeTab`, `settings`.

### Backend
- Node.js (Express/Fastify) или Python (FastAPI).
- Сервис сбора контекста (site + web snippets + social signals).
- Сервис генерации идей.
- Сервис диалога/опроса и финальной консультации.
- Rate limiting, retry-policy, структурные логи.

### LLM
- Основная модель: GPT-6 Sol (или эквивалент в момент релиза).
- Разделение промптов: `analyze`, `ideas`, `chat-questions`, `final-consultation`.

## 4. API-контракты (обязательный минимум)
### `POST /api/analyze`
**Request**
```json
{ "url": "https://company.com" }
```
**Response**
```json
{
  "analysisId": "an_123",
  "status": "done",
  "companyContext": "...",
  "sources": [{ "title": "...", "url": "https://..." }],
  "warnings": ["...optional..."]
}
```

### `POST /api/ideas/generate`
**Request**
```json
{ "analysisId": "an_123" }
```
**Response**
```json
{
  "ideas": [
    { "id": "idea_1", "title": "...", "description": "..." }
  ]
}
```
Требование: всегда ровно 5 элементов.

### `POST /api/ideas/regenerate`
**Request**
```json
{ "analysisId": "an_123", "excludeIdeaIds": ["idea_1", "idea_2"] }
```
**Response:** как у `/api/ideas/generate`.

### `POST /api/chat/start`
**Request**
```json
{ "analysisId": "an_123", "ideaId": "idea_3" }
```
**Response**
```json
{
  "chatId": "chat_42",
  "greeting": "Вы выбрали проект ...",
  "questions": [
    {
      "id": "q1",
      "text": "...",
      "type": "single",
      "options": [{ "id": "o1", "label": "..." }]
    }
  ]
}
```

### `POST /api/chat/message`
**Request**
```json
{ "chatId": "chat_42", "message": "...", "selectedOptions": ["o1"] }
```
**Response**
```json
{
  "assistantMessage": "...",
  "nextQuestion": null,
  "isFinal": true
}
```

## 5. UX/UI требования (фиксируем для разработки)
- Светлая тема.
- Опорный цвет: `#0A3D62` или `#D35400`.
- Блок статусов анализа: 5 состояний, плавная смена.
- Карточки идей: вертикальные, full width контейнера, 3–4 строки описания, `line-clamp`.
- Чат:
  - Табы с закрытием, horizontal scroll при переполнении.
  - Список проектов: фикс высота, без скролла.
  - Окно чата: фикс высота, внутренний скролл.
  - Запрет скролла страницы при активном чате (`body overflow hidden`).
- Mobile (`<=768px`): чат не ломает навигацию, без горизонтального скролла страницы.

## 6. Логика диалога
- На старте таба: приветствие + объявление 5–7 вопросов.
- `single`: отправка сразу после выбора.
- `multi`: кнопка «Отправить» активна только при `selectedOptions.length > 0`.
- Разрешен свободный текст (`free`), но основной сценарий — карточки ответов.
- Финальный ответ включает 6 секций:
  1. Суть проекта
  2. Потенциальная выгода
  3. Сроки (MVP/Full)
  4. Бюджет (S/M/L/XL)
  5. Риски
  6. Критически важные моменты

## 7. Безопасность и эксплуатация
- URL валидация на frontend и backend.
- Demo: ключ допускается в `localStorage` (шифрованный).
- Production: ключ только на сервере, клиент — через `httpOnly` cookie/session.
- Не логировать секреты.
- Retry до 2 попыток для `429/5xx/timeout`.
- Rate limit: от 5 анализов/мин/IP.
- Учет ограничений `robots.txt`; частичная деградация вместо полного fail.

## 9. Definition of Done (DoD)
Функция считается завершенной, если:
- Есть реализованный UI + backend endpoint + обработка ошибок.
- Есть smoke-проверка happy path и минимум 1 негативного кейса.
- Нет утечек секрета в логи/ответы.
- Поведение соответствует AC в этом документе.

## 10. Матрица приемки (короткая)
1. Ввод `yandex.ru` -> автонормализация до `https://yandex.ru`.
2. Показаны 5 статусов анализа последовательно.
3. Получены 5 уникальных карточек.
4. Перегенерация меняет набор без перезагрузки.
5. Открываются несколько чат-табов без поломки layout.
6. Для `multi` без выбора отправка недоступна.
7. Финальная консультация содержит 6 обязательных секций.
8. При частичной недоступности источников анализ завершается с warning.

## 11. План реализации по спринтам
- **Спринт 1 (P0):** end-to-end MVP поток (analyze -> ideas -> chat -> final).
- **Спринт 2 (P1):** надежность, UX-ошибки, mobile-полировка, регресс.
- **Спринт 3 (P2):** расширения и интеграции.

## 12. Зависимости и риски
- Зависимость от доступности внешних источников/поиска.
- Риск нестабильного парсинга сайтов с тяжелым JS/anti-bot.
- Риск разрастания контекста LLM -> нужен контроль размера и саммари.
- Риск хранения ключа на клиенте -> в prod только серверный ключ.
