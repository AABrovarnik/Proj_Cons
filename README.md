# Консультант по проектам (MVP)

Демо-приложение по ТЗ: анализ сайта компании -> генерация 5 AI-идей -> обсуждение в чат-табах -> финальная консультация.

## Запуск

```bash
npm install
npm run dev
```

Сервер поднимается на `http://localhost:3001`.

## Что реализовано

- Экран анализа URL с 5 шагами прогресса.
- Выбор уровня модели для анализа: `basic` / `standard` / `advanced`.
- API анализа `POST /api/analyze` с нормализацией URL.
- Генерация и перегенерация 5 идей:
  - `POST /api/ideas/generate`
  - `POST /api/ideas/regenerate`
- Чат с табами и опросом `single/multi/free`:
  - `POST /api/chat/start`
  - `POST /api/chat/message`
- Финальная консультация в требуемой структуре.
- Модальное окно настроек с сохранением API-ключа на backend.
- Восстановление UI-состояния (идеи, табы, активный чат) после перезагрузки.
- Toast-уведомления и улучшенные ошибки.

## LLM-режимы

- **Fallback (по умолчанию):** если ключ не задан, используются шаблонные генерации.
- **LLM-режим:** если ключ задан в настройках, backend использует OpenAI Responses API.
- **Уровни модели:** выбор уровня влияет на конфигурацию модели и температуру генерации для идей и финальной консультации.

## API настроек

- `GET /api/settings` — статус backend-ключа, дефолтный уровень и маппинг моделей.
- `POST /api/settings` — установка параметров:
  - `{ "apiKey": "sk-..." }` — установить ключ
  - `{ "apiKey": "" }` — очистить ключ
  - `{ "modelLevel": "basic|standard|advanced" }` — задать уровень модели

## Ограничения текущего MVP

- Внешний поиск/соцсети сейчас представлены упрощенно (в контексте фиксируется как сигнал для ручной проверки).
- Состояние хранится в памяти процесса backend и сбрасывается при рестарте.
- Без ключа OpenAI приложение работает в fallback-режиме.

## Основные файлы

- `src/server.js` — backend API и бизнес-логика MVP.
- `public/index.html` — структура интерфейса.
- `public/styles.css` — стили, layout, адаптив.
- `public/app.js` — клиентская логика шагов, идей, чата и настроек.
